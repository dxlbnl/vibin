title: Capture (recording knowledge automatically)
type: mechanism
status: draft

The keystone of [the loop](the-loop.md): a task must **record what it learned without anyone choosing to
write it down**. If capture depends on goodwill it doesn't happen — that is exactly
[pain P6](../research/vibin-painpoints.md).

Shape (to be proven — see [open questions](open-questions.md)):
- A **hook** observes the task (prompt, edits, result) and writes raw candidates to scratch — cheap,
  deterministic, off the critical path.
- At [close](gates.md), candidates are **distilled**: kept as an [atom](the-atom.md) (deduped, one home,
  linked) or dropped. Most are dropped; that is fine.
- A candidate becomes durable only if it is *reusable* — a fact a future task would re-derive, or a pattern
  that recurred. Audit narration is **not** knowledge ([what belongs](what-belongs.md)).

**Why:** capture is the highest-risk assumption in the whole model ([what Vibin is](what-vibin-is.md)). Design
it first and cheapest; if knowledge doesn't accumulate usefully, the model is wrong — learn that early.
