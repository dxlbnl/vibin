Two loops run together. This atom is the **knowledge loop** — how doing work makes the wiki grow and the wiki
makes the next work better. For *where tasks come from and how one is executed*, see
[the work loop](the-work-loop.md).

The knowledge loop, one cycle per task:

1. **Work** — an agent does a task from the current [sprint](sprints.md), at the lightest ceremony that fits
   ([right-sizing](right-sizing.md), [gates](gates.md)).
2. **Capture** — the task records what it learned as one or more [atoms](the-atom.md), cheaply and
   *automatically* (a [gate](gates.md), not a good intention).
3. **Integrate** — each atom is filed into the wiki: deduped, one canonical home, linked to neighbours.
4. **Retrieve** — the *next* task pulls the relevant atoms back in before starting ([retrieval](retrieval.md)).
5. **Better work** — because the agent read the wiki, the next task is cheaper and safer. Repeat.

The **run log** is scratch — disposable once its knowledge is integrated. The **wiki** is what survives
([the run log](the-run-log.md), [sprints](sprints.md)).

**Why:** the keystone is steps 2 and 4 ([capture](capture.md), [retrieval](retrieval.md)).
[Pain P6](../research/vibin-painpoints.md) happened because capture was manual (nobody did it) and the wiki was
never read. If capture and retrieval aren't near-free *and* enforced, the wiki dies.
